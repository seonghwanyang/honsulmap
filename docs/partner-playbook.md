# 혼술맵 사장님 수익화 플레이북

**작성:** 2026-07-05 · **성격:** 실행 플레이북 (기능 분해는 [roadmap.md](roadmap.md) 참고)
**한 줄 요약:** 방문 증명(리딤+체크인)을 쌓아 → 사장이 가치를 숫자로 보게 하고 → 그 숫자로 유료 전환한다.

---

## 0. 북극성

> **혼술맵 경유 방문 = 체크인 + 혜택 사용(리딤)**

- 조회수·가입자·인증 사장 수는 보조 지표. **이 숫자 하나만 오르면 구독·광고 전부 따라온다.**
- 형 대시보드(admin)와 사장 리포트에 **같은 숫자**가 찍혀야 "봤죠? 좋죠?"가 성립한다.
- 유료화 타이밍은 날짜가 아니라 **숫자 트리거**로 정한다 (아래 Phase별).

## 1. 확정된 시스템 설계

### 1.1 리딤 플로우 (어트리뷰션의 심장)

**혜택 정보는 누구나 봄. [사용하기] 버튼만 GPS 300m 게이트.**

```
손님: 혜택 상세 → [사용하기]
  → GPS 확인 (가게 300m 이내 — 체크인 로직 재사용)
  → "직원에게 보여주세요" 화면
     · 혜택명 큼직 + 가게명 + 실시간 시계 + 3분 카운트다운 + 움직이는 배경(스크린샷 방지)
  → 완료 → benefit_redemptions 기록 + 자동 체크인 + 스탬프 적립 (전부 한 방)
```

- **GPS 거부/실패 시:** "위치를 확인할 수 없어요" → 직원 PIN 입력으로 우회 (완전 차단하지 않음)
- **PIN (사장 설정, 선택):** 리딤 완료에 사장이 정한 4자리 입력 필요.
  - 역할 ①: 악용 방지 — 사장의 "손해 볼까 봐" 공포를 해소하는 **세일즈 포인트** ("악용 방지 장치 있습니다")
  - 역할 ②: 사장이 PIN을 눌러줄 때마다 **앱이 일하는 걸 직접 봄** = 리텐션 접점
  - Phase 1은 눈검증 기본 + PIN은 옵션. 악용 사례 나오면 기본값 전환.
- **횟수 제한:** 혜택별 1인 1회 기본, 사장이 "매 방문마다 가능"으로 변경 가능.

**무결성 3중 구조 — 전부 "가게 보호" 프레이밍:**

| 층 | 무엇 | 역할 |
|---|---|---|
| ① 서버 기록 | 1인 1회 중복 차단 (진짜 중복 방지는 여기) | 돈 안 샘 |
| ② GPS 300m | "지금 매장에 있다" 증명 | 허위 사용 차단 |
| ③ PIN | 가게측 최종 승인 | 사장의 검사권 |

- 사장 멘트: *"중복은 시스템이 막고, 위치는 GPS가 검사하고, 최종 승인은 사장님이 하세요."*
- 손님 문구: *"가게 확인을 위해 매장에서만 열 수 있어요"* — 가게측 검사 명분 + 방문 유도 겸용.

### 1.2 체크인 자동화 3종 (버튼이 아니라 부산물로)

1. 리딤하면 → 자동 체크인
2. **가게 QR** 스캔 → 자동 체크인 (QR은 사장 대시보드에서 PDF 다운로드 → 카운터 부착. 워크인 손님을 퍼널로 흡수)
3. RSVP한 사람이 당일 가게 근처에서 앱 열면 → "도착하셨네요! 체크인?" 원탭

### 1.3 스탬프 · 뱃지 (누를 이유)

- **스탬프:** 사장이 "N회 방문 = 보상"(예: 3번 = 하이볼 1잔) 설정 → 체크인이 곧 스탬프.
  사장 락인 + 손님 락인 + 어트리뷰션이 한 기능에서 다 나옴.
- **뱃지:** 지역 정복("애월 4/26"), 가게별 단골 레벨, **채팅 닉 옆 "다녀옴/단골" 표시** (신뢰+과시)

### 1.4 혜택 모음 페이지 (`/benefits`)

- 거지맵 경유쇼핑 스타일: 헤더 + 검색 + 정렬(마감임박/신규) + 업종·지역 칩 + 카드 그리드(가게명·혜택·지역·D-day) + 이용방법 1-2-3 + 유의사항
- 카드 탭 → 가게 상세/리딤
- **게이팅 타이밍:** 베타 = 전체 노출(페이지 풍성) → 유료화 날 = Plus만 노출. *"이 페이지에서 빠지기 싫으면 구독"* — 노출 상품의 실체.

### 1.5 주간 리포트 시스템

**신설 테이블 2개:**

```sql
benefit_redemptions (id, spot_id, user_id, benefit_title(스냅샷), method('eye'|'pin'), redeemed_at)

spot_weekly_stats (            -- 주간 스냅샷, 매주 월요일 집계
  spot_id, week_start,
  views, favorites_added, checkins, redemptions, ig_clicks, story_plays,
  rank_region, rank_national, cohort_size,
  PK (spot_id, week_start)
)
```

**집계 잡:** 주 1회 (Vercel Cron API route, 또는 IG 스크랩 도는 PC 작업스케줄러에 편승 — 검증된 방식)

**표시 (결과물을 직관적으로):**
- **사장:** `/partner/spot/[id]` → "주간 리포트" 섹션. 이번 주 카드 + 지난주 대비 변동 + 주별 히스토리 그래프
- **운영자:** `/admin/performance` — 전체 리딤/체크인 누적·추이, 활성 사장 수(주1회+ 접속), 가게별 기여 순위, 유료화 트리거 게이지
- **발송:** 1단계 = 웹 + 푸시 → 2단계 = 카카오 알림톡 (사업자 이미 있음 → 비즈메시지 신청만)

**리포트 구성 (매주 월요일):**

| 섹션 | 예시 | 데이터 |
|---|---|---|
| 헤드라인 | 조회 142(▲22%) · 새 찜 5 · 방문 인증 7 · 혜택 사용 3 | 기존 + 리딤(신설) |
| 순위 | 애월 26곳 중 3위(▲2) · 전국 12위 | 기존 + 주간 스냅샷 |
| 유입 | 지도 61% · 검색 24% · 피드 15% | `entry_source` |
| 피크 | 금·토 21~23시 | `spot_views` 시각 |
| 잠재 고객 | "찜했지만 아직 안 온 42명" | 찜 − 체크인 교집합 |
| 인스타 송출 | 혼술맵→내 인스타로 19명 | `ig_click` |
| 코칭 한 줄 | "스토리 올린 날 조회 2.1배 — 금요일에 올리세요" | 스토리×조회 상관 |

**우리만 주는 고급 리포트 (네이버·인스타 불가):**
1. **동네 벤치마크** — "애월 게하 평균 조회 89, 사장님은 142(+60%)" ← 옆집 데이터를 우리만 가짐
2. **수요 예보** — 지역 전체 트렌드로 "다음 주말 수요 ▲, 혜택 걸어두세요"
3. **잠재 고객 큐** — "찜 42명 미방문 → 푸시 한 번이면 닿습니다" ← **Plus 업셀이 리포트에 내장**
4. **스토리 ROI** — 올리기 좋은 요일/시간 코칭 (사장의 인스타 컨설턴트 포지션)

### 1.6 사장 공지/메시지 시스템

- `partner_notices` 테이블 (title, body, type('banner'|'popup'), created_at, active) → admin에서 작성 → **모든 사장 대시보드(/partner, /partner/spot/*) 상단 배너**
- **UI 결정 (2026-07-05 확정): 배너 + 아카이브.** 벤치마크(배민 사장님·네이버 스마트플레이스·토스 상점관리자) 전부 "배너=지금 볼 것 / 아카이브=놓친 것 / 팝업=크리티컬 1회" 3종 역할 분담.
  - **배너**: 대시보드 상단, 최신 활성 공지 1개만. `[자세히 보기] [지난 공지 ›]` 액션. 닫으면(읽음 처리) 접힘.
  - **아카이브**: `/partner/notices` — 공지 리스트(제목·날짜·NEW 뱃지) → 항목 탭하면 본문 펼침. 배너 닫아도 여기서 다시 봄.
  - **팝업**: 중요 공지만(유료화 예고 등) `type: 'popup'` → 1회만 팝업, 확인 후 배너로 강등.
- 신기능 안내·유료화 예고·이벤트 공지 채널. 개인 메시지는 1단계에선 공지+뱃지로 충분, 필요해지면 인박스 추가.
- (알림톡 뚫리면 공지도 알림톡 동시 발송)

## 2. 단계별 로드맵 — 트리거는 날짜가 아니라 숫자

### Phase 0 — 기반 구축 (지금 ~ 2주)
| | |
|---|---|
| 빌드 | ① 리딤+자동 체크인 ② `/benefits` 페이지 ③ `/admin/performance` ④ 공지 배너 |
| 완료 기준 | 테스트 가게로 **리딤 1건 E2E** (사용하기→PIN→기록→admin에 찍힘) |
| 동결 | 위 4개 외 기능 개발 금지 |

### Phase 1 — 베타 사장 모집 (인증 0 → 30 / 활성 15)
| | |
|---|---|
| 액션 | DM 캠페인 시작 (하루 20~30개, 개인화 순위 훅), 야화 본사 컨택(지점 일괄) |
| 온보딩 기준 | 인증만으론 실패. **인증 + 혜택 1개 등록 + 채팅방 오픈**까지 손잡고 (전화/방문 불사) |
| 주시 지표 | DM 응답률(목표 15%+), 인증→활성 전환율(50%+), 혜택 등록 수 |
| 목표 (4주) | 인증 30 / **활성(주1회 접속) 15** / 혜택 15개 / **첫 리딤 10건** |

### Phase 2 — 활성화 (활성 15 → 30 / 월 리딤 50)
| | |
|---|---|
| 트리거 | 활성 사장 15+ & 리딤이 주 5건+ 발생하기 시작 |
| 빌드 | 스탬프, 게하 파티 RSVP, 오늘밤 신호(원탭 브로드캐스트), 주간 리포트 자동 발송 |
| 지역 전략 | **한 지역 밀도 80%** 먼저 (홍대/합정 혼술바 또는 애월 게하) — 전국에 얇게 X |
| 주시 지표 | 주간 활성 사장, 리딤/주, 리포트 오픈율(50%+), 지역 커버리지 |
| 목표 | 활성 30 / 월 리딤 50 / 한 지역 커버 80% |

### Phase 3 — 유료화 준비 (활성 30+ / 월 리딤 100+)
| | |
|---|---|
| 트리거 | **월 리딤 100건** 돌파 (= "보낸 손님" 스토리가 사장마다 생김) |
| 액션 | 알림톡 세팅, 가격 확정, 결제(토스페이먼츠/포트원) 연동, **유료화 D-30 예고 공지** |
| 예고 내용 | "베타 종료 예정 · 파운딩 멤버 조건(아래) · 지금까지 사장님 가게 성과 N건" |
| 주시 지표 | 파운딩 전환 의사(사전 신청), 잠재 고객 큐 크기, 리포트 오픈율 |
| 목표 | 파운딩 사전 신청 20곳+ |

### Phase 4 — 유료화 스위치
| | |
|---|---|
| 액션 | Plus 런칭. 혜택 페이지 노출·푸시·상세 리포트 잠금 (**리딤 자체는 안 잠금** — 어트리뷰션은 계속 쌓여야 함) |
| 목표 | 활성 사장의 **30~40% 결제** (활성 40명이면 12~16곳 = 월 12~30만원 시작) |
| 이후 | 노출 상품(지역 상단 고정) 단건 판매 → 슬롯 희소성 → 입찰 |

## 3. 유료화 설계

### 요금제

| | 무료 (영구) | **Plus ₩19,900/월** (파운딩 ₩9,900) |
|---|---|---|
| 지도 등록·스토리 노출 | ✅ | ✅ |
| 채팅방 | ✅ | ✅ |
| 기본 리포트 (헤드라인 숫자만) | ✅ | ✅ |
| **혜택 모음 페이지 노출** | 베타만 | ✅ |
| **찜 손님 푸시** (월 4회 제한) | ❌ | ✅ |
| **상세 리포트** (벤치마크·피크·잠재큐·스토리ROI) | ❌ | ✅ |
| 스탬프 설정 | ❌ | ✅ |
| 오늘밤 신호 (원탭 브로드캐스트) | ❌ | ✅ |
| 노출 상품 (지역 상단 고정 등) | — | 단건 별도 판매 |

- 가격 논리: 리딤 10건 × 객단가 3만원 = 월 30만원 기여 추정 → 구독료가 그 1/15. "하이볼 4잔 값".
- 푸시 월 4회 제한 = **소비자 스팸 방어** (소비자가 진짜 자산. 사장 과금이 소비자 경험을 깎으면 전체가 무너짐)

### 파운딩 멤버 (유료화 명분 + 초기 락인)

- **조건:** 유료화 스위치 이전에 ①인증 ②혜택 1개 이상 등록 ③월 1회 이상 접속 — 셋 다 충족한 가게
- **혜택:** Plus **평생 50%** (₩9,900) + 대시보드·가게 페이지에 "파운딩 멤버" 뱃지
- **마케팅:** "첫 30곳 한정" 프레임 (실제 충족자가 넘으면 전원 인정하되 희소성 유지)
- **약속:** 베타 때 쓰던 기능은 파운딩 멤버에게 안 뺏음 (신뢰 자산)

### 결제 플로우 유도 (베타 → 유료)

```
D-30  공지 배너 + DM: "베타 종료 예정. 파운딩 조건 안내"
D-7   개인화 리마인드: "베타 기간 사장님 가게 성과 — 방문 인증 N건, 혜택 사용 M건.
      파운딩가 ₩9,900로 이어가시겠어요?"
D-Day 기능 잠금 + 결제 페이지 (토스/포트원 정기결제). 잠금 화면에 그 가게의 실제 숫자 표시
D+7   미결제 활성 사장에게 마지막 개인 연락 (전화가 최고)
```

## 4. 사장 세일즈 자료

### 보여줄 혜택 + 근거 (전부 실제 숫자로 뒷받침)

| 사장에게 하는 말 | 근거 데이터 |
|---|---|
| "이미 손님들이 사장님 가게를 보고 있어요 — 지난주 조회 N회" | `spot_views` |
| "N명이 사장님 가게를 찜하고 새 소식을 기다려요" | `favorites` |
| "혜택 걸어두면 **온 손님이 숫자로 찍힙니다**" | `benefit_redemptions` |
| "매주 월요일, 숫자로 된 성적표를 보내드려요" | `spot_weekly_stats` |
| "손님 문의를 채팅으로 바로 받아요 (예약 창구)" | chat |
| "옆집 대비 어디쯤인지 — 애월 26곳 중 M위" | 코호트 순위 |
| "악용 걱정 없어요 — 위치 확인 + 사장님 PIN 없인 사용 처리 안 됩니다" | GPS+PIN |

### 심리 화법 — "초반에 손님 적을 텐데" 어떻게 말하나

- ❌ **"한두 달 지나면 많이 쓸 거예요"** — 검증 불가한 미래 약속. 신뢰만 소모.
- ✅ **현재 증거:** "지금도 한 주에 N명이 사장님 가게 페이지를 봐요. 이건 이미 일어나는 일이에요."
- ✅ **손실 프레임:** "이 노출이 지금 주인 없이 흘러가고 있어요. 혜택 하나만 걸어도 그 시선이 방문으로 바뀝니다."
- ✅ **무위험:** "무료고, 1분이면 되고, 별로면 안 쓰시면 그만이에요."
- ✅ **사회적 증명:** "야화는 벌써 4개 지점이 들어왔어요. 내잔도 3개 지점 등록했고요."
- ✅ **정직한 기대 + 동행 프레임:** "초반엔 주 몇 건일 거예요. 대신 **그 몇 건이 전부 기록으로 남고, 매주 제가 숫자로 보여드립니다.** 같이 키우는 거예요."
- 핵심 원칙: **약속은 미래로 하지 말고, 증거는 현재로 대라.** 기대치는 낮게 잡아주고 숫자로 초과 달성하는 게 신뢰 축적 루트.

### 첫 DM — A/B/C 3버전 (성향 따라 골라 쓰거나, 20개씩 나눠 A/B 테스트)

**A. 숫자 훅형 (데이터로 어필 — 기본값 추천)**
> [가게명] 사장님 안녕하세요! 혼술바/게하 실시간 지도 **혼술맵**이에요 😊
> [가게명]이 저희 지도에 올라가 있는데, **지난주에만 N명이 사장님 가게 페이지를 봤어요.**
> ([지역] [업종] 중 조회수 상위 M%예요!)
> 사장님 인증하시면 무료로 — 우리 가게 통계 📊 / 혜택·쿠폰 등록 🎁 / 손님 채팅 💬 을 쓸 수 있어요.
> honsulmap.com → 사장님 센터에서 1분이면 끝나요. 편하게 답 주세요 🙌

**B. 손실 회피형 (방치 프레임 — 조회수 높은 가게에)**
> [가게명] 사장님 안녕하세요, 혼술맵이에요!
> 손님들이 혼술맵 지도에서 [가게명]을 계속 보고 있는데, 지금은 **주인 없이 노출만 되고 있어요.**
> 사장님이 직접 관리하시면 그 시선을 방문으로 바꿀 수 있어요 — 혜택 하나 걸어두면 "혜택 보고 온 손님"이 숫자로 찍힙니다.
> 무료예요. 인증 1분. 관심 있으시면 답 주세요 :)

**C. 캐주얼 단문형 (부담 최소 — 답장률 테스트용)**
> 사장님 안녕하세요! 혼술 손님들 지도 앱 혼술맵인데요,
> [가게명] 보고 찾아가는 손님들이 있어서 연락드렸어요 ㅎㅎ
> 가게 페이지 직접 관리해보실래요? (무료·1분)

공통 규칙:
- **개인화 1줄 필수** (조회수 N or 순위 M% — admin 데이터에서 뽑아서)
- 하루 20~30개 상한, 보내기 전 팔로우/스토리 좋아요 1개(워밍업)
- 이모지 2~3개까지, 링크는 1개만

### 시나리오별 대응 스크립트

| 시나리오 | 대응 |
|---|---|
| **① 무응답 (5~7일)** | 딱 1회 후속, 팔지 말고 숫자만: *"지난주 [가게명] 조회 N회 나왔어요! 그냥 숫자만 공유드려요 :)"* — 그래도 무응답이면 리스트에 남기고 다음 배치. 월 1회 숫자 공유는 지속 (스팸 아니게) |
| **② "이게 뭐예요?"** | *"제주·서울 혼술바/게하 인스타 스토리를 모아서 '오늘 어디가 살아있나' 보여주는 지도예요. 손님들이 스토리 보고 가게를 찾아가요. honsulmap.com 한번 열어보시면 바로 감 오실 거예요!"* |
| **③ "돈 내야 해요?"** | *"아니요, 지금은 전부 무료예요. 나중에 유료 기능이 생겨도 **초기에 함께해주신 사장님들은 파운딩 멤버로 평생 반값**이에요. 지금 쓰시는 기능을 뺏는 일은 없어요."* |
| **④ "효과 있어요? 손님 진짜 와요?"** | 정직+동행 프레임: *"지금도 주 N명이 사장님 가게를 보고 있어요(이건 이미 일어나는 일이에요). 방문 전환은 초반엔 주 몇 건일 수 있는데, **오는 손님이 전부 기록으로 남고 매주 숫자로 보여드려요.** 같이 키워보시죠."* — 미래 과장 금지 |
| **⑤ "어떻게 하는 건데요?" (긍정)** | 즉시 온보딩: *"지금 이 DM 주신 것 자체가 계정 인증이에요! honsulmap.com → 사장님 센터 → [가게명] 소유 신청만 눌러주시면 제가 바로 승인해드릴게요. 등록(혜택·채팅방)은 제가 전화로 같이 해드려도 돼요."* → **혜택 1개 + 채팅방 오픈까지 완료시키는 게 목표** |
| **⑥ "우리 가게 빼주세요"** | 즉시 수용, 방어 금지: *"네 바로 내릴게요! 처리했습니다. 혹시 나중에 생각 바뀌시면 언제든 연락 주세요 :)"* → 실제로 즉시 삭제. 지역 커뮤니티에서 평판이 자산 |
| **⑦ "인스타 사진 왜 마음대로 써요?" (스크래핑 항의)** | *"스토리를 저장하는 게 아니라 인스타 원본 링크를 그대로 보여드리는 거라, 사장님 인스타로 손님이 넘어가는 구조예요(지난주 IG 이동 N명). 그래도 원치 않으시면 바로 제외해드릴게요."* → 원하면 즉시 제외. ⑥과 동일하게 순순히 |
| **⑧ "나중에요 / 바빠요"** | *"넵 바쁘신데 답 주셔서 감사해요! 부담 없이 매달 가게 숫자만 공유드릴게요. 필요해지면 그때 말씀 주세요 :)"* → 월 1회 숫자 공유 리스트로 |
| **⑨ "누구세요? 사기 아니에요?"** | 실명 공개: *"혼술맵 운영자 양성환입니다. 사이트는 honsulmap.com이고, [야화/내잔 등] 이미 N곳 사장님들이 쓰고 계세요. 결제 요구는 일절 없어요 — 프로필에서 확인하실 수 있어요."* |
| **⑩ "네이버/인스타 하는데 왜 또?"** | 차별점 1개만: *"네이버는 '존재하는 가게', 저희는 **'오늘 밤 살아있는 가게'**를 보여줘요. 혼술·게하 파티 손님만 모여 있는 지도라 타겟이 달라요. 그리고 옆 가게 대비 순위 같은 건 네이버가 못 보여드리는 거예요."* |

**⑤로 전환된 사장 온보딩 체크리스트 (당일 완료 목표):**
1. 소유 신청 승인 (DM 답장 = 소유 증명, 코드 생략 가능)
2. 혜택 1개 등록 (같이 정해주기: "웰컴드링크 1잔" 같은 부담 없는 것)
3. 사용 확인 PIN 설정 여부 안내 ("악용 걱정되시면 PIN 켜세요")
4. 채팅방 개설
5. "매주 월요일에 숫자 보내드릴게요" 예고 → 주간 리포트 루프 시작

## 5. 운영자(형) 행동 지침

### 메시지 캘린더

| 시점 | 뭘 보내나 |
|---|---|
| **매주 월요일** | 주간 리포트 (자동화 전엔 수동으로라도 — **이게 제일 중요**) |
| 온보딩 D+1 | "혜택 등록 도와드릴까요?" |
| **첫 리딤 발생 순간** | 축하 + 스크린샷 ("첫 손님이 혜택 쓰고 갔어요!") — 이게 사장의 aha moment |
| 월 1회 | 신기능/공지 (공지 배너 + DM) |
| 유료화 D-30 / D-7 / D-Day | §3 결제 플로우 참고 |

### 시기별 주시 지표

| Phase | 매일/매주 볼 것 |
|---|---|
| 1 | DM 응답률, 인증→활성 전환율, 혜택 등록 수 |
| 2 | 주간 활성 사장 수, 리딤/주, 리포트 오픈율, 지역 커버리지 |
| 3 | 파운딩 사전 신청 수, 월 리딤 100 게이지 |
| 4 | 결제 전환율, 결제 후 30일 유지율, 소비자 푸시 수신거부율 |

### 하지 말 것

1. **기능 욕심** — Phase 0의 4개 외 개발 동결. 채팅 고도화·통계 치장 전부 뒤로.
2. **전국 확장 욕심** — 한 지역 밀도 80% 전에 다른 지역 영업 금지 (요청 오는 건 받되, 영업력은 한 곳에).
3. **사장 스팸 허용** — 푸시 월 4회 하드리밋. 소비자 이탈하면 팔 게 없어짐.
4. **뻥튀기·과잉 약속** — 숫자는 있는 그대로. 신뢰 자산 잃으면 이 사업 끝.
5. **베타 기능 회수** — 파운딩 멤버가 쓰던 걸 뺏으면 여론 터짐. 잠금은 신규에게만.
