# 혼술맵 테이블 서비스 v1 스펙 — "우우 풀시스템"의 SaaS화

2026-08-19 · 파일럿: 친한 가게 1곳 (가게명·좌석수·포스 기종 확인 예정)
벤치마크 근거: `docs/qr-table-benchmark-2026-08-19.md` (우우 기능 전체 + 태그히어 ₩0 아이템 패턴)

원칙: **우우가 실증한 기능을 "한 가게 수제작"에서 "가게마다 켜고 끄는 SaaS"로.** 모든 기능은 가게별 토글 — 소셜 없는 조용한 바는 메뉴+주문만 켜면 됨.

---

## 0-1. 아키텍처: 멀티테넌트 (가게별 새 사이트 아님)

- **한 코드베이스·한 DB·한 배포.** 가게가 가입하면 별도 사이트를 만드는 게 아니라, `spot_id` 기준으로 데이터가 갈라지는 **가게 전용 공간이 자동 생성**된다 (SaaS 표준 멀티테넌시).
- **손님 URL**: 온보딩 완료 즉시 `honsulmap.com/t/{slug}` 자동 발급 (+ 좌석별 QR `?seat=N`). 우리가 수동으로 만들 것 없음. 도메인 분리·재배포 없음.
- **사장님 관리**: 새 URL 없음 — **기존 partner 대시보드에 "테이블" 탭 추가.** 계정·가게 클레임(partner claim)·로그인 전부 재사용. 사장님은 로그인 하나로 채팅 관리+혜택+테이블 서비스를 한 화면에서.
- **혼술맵 미등록 가게도 가입 가능**: 온보딩에서 스팟 생성부터 (B2B 판매를 지도 등록 여부와 분리 — 지도 노출은 가입 보너스 혜택으로 포지셔닝).
- **v2 유료 옵션 — 브랜드 도메인**: 우우처럼 정체성 강한 가게엔 `{slug}.honsulmap.com` 서브도메인 또는 자체 도메인 연결 (Next.js 호스트 기반 rewrite + Vercel 와일드카드). v1엔 안 함.

## 1. 화면 구성 총람

```
[손님]   QR 스캔 → 체크인 → 홈(테이블 모드) → 메뉴/주문·좌석맵·퀘스트·술게임·내정보
[사장님] partner 확장 → 배치도 에디터·메뉴 관리·주문 보드·퀘스트 관리·라이브 상태·마감
[운영자] admin 확장 → 가게 온보딩(모드 토글·QR 생성)·사용 통계
```

## 2. 손님 페이지 (`/t/{storeSlug}` — QR 진입)

### 2-1. QR & 진입
- 좌석마다 고유 QR: `/t/{slug}?seat=12` (단축 URL, 스캔 카운트 기록)
- 좌석 QR = 실물 스탠드/스티커 (인쇄물 우리가 제작·배송)

### 2-2. 체크인 (소셜 모드 ON 가게)
우우 방식 그대로, 마찰 최소화:
- 좌석번호(QR이면 자동) + **휴대폰 뒤 4자리** (세션 복구 키 — 해시 저장)
- **성별(필수)** · 나이대(필수) → 이후 선택: MBTI · 오늘의 목적("편하게 대화하고 싶어요"~"조용히 마시고 싶어요") · 선호 분위기 · TMI 한 줄 · 선호 술
- **좌석 정보 공개 토글** (성별은 항상 공개 — 우우 규칙)
- 개인정보 고지: "저장되지 않으며 영업 종료 후 자동 만료"
- 소셜 모드 OFF 가게: 이 단계 통째로 스킵 → 바로 홈

### 2-3. 홈 (테이블 모드)
- 상단: 가게 로고 + 현재 좌석 + "계산은 좌석번호를 직원에게" 안내
- **라이브 상태 배지**: "⚡빠르게 자리 차는 중" 등 (사장님이 원터치 설정)
- 오늘의 퀘스트 N개 (접힘)
- 큰 버튼: 🥃 주문하러 가기
- 매장 안내 블록: 와이파이 비번 복사 · 화장실 위치 · 이용 규칙
- 하단 탭: 좌석 | 메뉴 | 퀘스트 | 술게임 | 내 정보

### 2-4. 메뉴 & 주문
- 카테고리 탭 (이벤트/위스키/칵테일/안주...) — 사장님이 편집
- 품목: 이름·가격·설명·품절 표시·옵션(예: 하이볼 변경 +2,000)
- 담기 → 요청사항("얼음 적게") → 주문
- **₩0 아이템** (태그히어 패턴 — 모든 인터랙션을 주문 파이프로):
  - 직원 호출 ₩0 / 직원에게 추천받기 ₩0 / 불편·빌런 신고 ₩0 (사장님만 봄)
  - **"그냥 이유없이 한 잔 드리고 싶어요"** — 익명 선물 (우우 시그니처, 소셜 모드 전용)
- 주문 후: 내 주문내역 + 좌석 누적 합계 (후불 카운터 결제 — 결제 기능 없음)
- 이벤트 상품 지원: "꽝없는 뽑기 ₩8,000" 같은 유료 이벤트도 그냥 메뉴 품목으로

### 2-5. 좌석맵
- 구역별(내측/창측/바...) 렌더 — 사장님 배치도 설정을 그대로 그림
- 좌석: 빈자리/사용중/내자리 + (공개 세션) 성별 표시, 탭하면 공개 프로필
- 버퍼석(자리이동 대기) 타입 지원

### 2-6. 퀘스트 (소셜/이벤트 모드)
- 오늘의 퀘스트 목록 (보상 명시, HIDDEN 지원)
- "달성했어요" 탭 → 사장님 보드에 알림 → 사장님이 확인·보상
- v1은 자가신고+사장님 확인 (자동 판정은 주문 연동 v2)

### 2-7. 술게임 — 도감이 아니라 "플레이 툴" (우우 발전형 ⭐)
우우는 게임 규칙을 글로 보여주는 도감까지만. 우리는 **폰에서 직접 플레이**하게 한다:
- **v1 플레이 툴** (폰 1대로 돌아감, 동기화 불필요 — 각각 하루 안팎 개발):
  - 벌칙 룰렛 (참가자 이름 넣고 돌리기)
  - 폭탄 타이머 (랜덤 시간 폭발 — 폭탄돌리기용)
  - 사다리타기 (벌칙/계산 정하기)
  - 주사위·랜덤픽 ("누가 마실까")
  - 질문카드 덱 (아이스브레이킹 질문 랜덤 — 처음 만난 사람용)
- **v1.5**: 실시간 빙고 (같은 가게 체크인 세션끼리 Realtime 동기화 — 옆 테이블과 대결)
- **벌칙→주문 원탭**: 게임 결과 화면에 "벌칙주 담기" 버튼 (사장님이 벌칙 메뉴 지정, 예: 데킬라샷)
  — **게임이 곧 매출이 되는 고리.** 이게 우우 대비 핵심 발전.
- 도감(규칙 열람)은 그대로 제공 + 가게별 커스텀 게임·벌칙 메뉴 등록

### 2-8. 혼술맵 연결 (우리만의 훅)
- 체크인 화면 하단: "혼술맵 계정으로 스탬프 적립" (선택 로그인 → user_spot_events 연동)
- 퇴장 후 리뷰 유도 푸시 (혼술맵 앱 설치자)
- 테이블 세션 발생 = 지도에 "지금 살아있는 가게" 신호 (라이브 상태와 합산)

## 3. 사장님 페이지 (partner 대시보드 확장)

### 3-1. 테이블 배치도 에디터 ⭐ (요청 핵심)
- **구역 추가** (이름: 내측/창측/문측/바 등, 순서)
- 구역 안에 **그리드 스냅 배치**: 셀 탭 → 좌석(번호 자동/수동) 또는 테이블 블록(장식) 지정
  - 자유형 캔버스 아님 — 우우 스크린샷 수준의 배치는 그리드로 충분, 개발비 1/5
- 좌석 속성: 번호, 타입(일반/버퍼), 활성화
- 저장 즉시 손님 좌석맵·QR 매핑 반영
- 좌석 추가/삭제 시 QR 재발급 목록 자동 표시

### 3-2. 메뉴 관리
- **최초 시드: 네이버 메뉴 가져오기** (naver_menus 수집분 → 원클릭 임포트)
- 카테고리 CRUD·정렬, 품목 CRUD, **품절 토글**, 옵션, ₩0 아이템 관리
- "오늘의 안주" 플래그 (홈 상단 노출)

### 3-3. 주문 보드 (영업 중 화면 — 태블릿/폰 거치)
- 신규 주문 실시간 팝업 + 소리 (Supabase Realtime)
- 카드: 좌석번호·품목·요청사항·경과시간 → [접수] [완료] [취소]
- ₩0 아이템은 색 구분 (호출=노랑, 신고=빨강, 선물=보라 — 선물은 대상 좌석 표시)
- 퀘스트 달성 알림 인입 → [보상 지급 완료]
- **좌석별 누적 합계 뷰** (카운터 계산 시 대조용)
- 백업 알림: 1분 미확인 시 사장님 폰 푸시 (기존 push 인프라) — 알림톡은 v1.5
- **영업 마감 버튼**: 전 세션 만료·프로필 삭제·일 요약 (주문액/체크인/퀘스트)

### 3-4. 퀘스트·이벤트 관리
- 템플릿 갤러리에서 선택 → 보상 문구 수정 → 활성화 (요일 반복 옵션)
- 기본 템플릿 8종: 시그니처 N잔 도장깨기 / 위스키 N잔→서비스 / MBTI 짝 찾기 / 첫 혼술 인증 / 혼자 왔어요 첫잔 / 스탬프 3방문 / 요일 이벤트 / 신메뉴 투표
- HIDDEN 토글

### 3-5. 라이브 상태 & 운영
- 원터치 상태: 🟢 자리 여유 / ⚡ 빠르게 차는 중 / 🔴 만석 / ☕ 오픈 준비 중 / 휴무
- 손님 홈 배지 + **혼술맵 지도 마커 배지 연동**
- 이용 규칙 편집 (우우 트러스트&세이프티 문구 기본 내장)

## 4. 운영자(우리) 어드민

- 가게 온보딩 마법사: 스팟 연결 → 모드 토글(주문/소셜/퀘스트/술게임) → 좌석 수 입력 → **QR 일괄 생성 + 인쇄용 PDF 내보내기**
- 사용 통계: 일별 스캔·체크인·주문 수·주문액·퀘스트 달성 (파일럿 성과 = 유료 전환 근거 데이터)

## 5. 데이터 모델 (Supabase 신규 테이블)

```sql
store_table_config   -- spot_id, modes(jsonb: order/social/quest/games), live_status, rules_md
store_zones          -- id, spot_id, name, sort
store_seats          -- id, zone_id, label, row, col, type(seat|block|buffer), active
table_sessions       -- id, spot_id, seat_id, phone4_hash, gender, age_band, mbti,
                     --   purpose, vibe, tmi, drink_pref, is_public, checked_in_at, expires_at
store_menu_categories-- id, spot_id, name, sort
store_menu_items     -- id, category_id, name, price, description, image, sold_out,
                     --   options(jsonb), zero_action(null|call|recommend|report|gift), sort
table_orders         -- id, spot_id, session_id, seat_label, status(new|accepted|done|canceled), created_at
table_order_items    -- order_id, item_name, price, qty, request, gift_target_seat
store_quests         -- id, spot_id, title, reward, hidden, active, repeat_dow(jsonb)
quest_claims         -- quest_id, session_id, status(claimed|rewarded), claimed_at
drinking_games       -- 공통 콘텐츠: title, min_p, max_p, tags, rules_md, penalty (spot_id null=공통)
```

- 세션 만료: `expires_at` = 당일 새벽 6시 기본, 마감 버튼 시 즉시. 만료 시 프로필 필드 null 처리 (개인정보 미보존 약속 이행)
- RLS: 손님은 자기 세션+공개 세션 read, 주문은 자기 세션 insert. 사장님은 spot 단위 (기존 partner claim 체계 재사용)
- Realtime 채널: `orders:{spot_id}`, `sessions:{spot_id}` (좌석맵 갱신)

## 6. 개발 순서 (파일럿 1곳 기준)

| 스프린트 | 내용 | 완료 기준 |
|---|---|---|
| S1 (1주) | 배치도 에디터 + 체크인 + 좌석맵 + 메뉴 관리(네이버 임포트) + 메뉴 보기 | 사장님이 배치도 그리고, 폰으로 체크인→좌석맵에 뜸 |
| S2 (1주) | 주문(장바구니→보드) + ₩0 아이템 + 좌석 합계 + 마감 + **토스포스 Open API 주문 주입** | 실주문이 보드와 가게 포스 양쪽에 뜸 |
| S3 (1주) | 퀘스트 + 술게임 플레이 툴(룰렛·타이머·사다리·랜덤픽·질문덱) + 라이브 상태(지도 연동) + QR PDF + 통계 | 가게에 QR 실물 설치, 풀플로우 실전 |
| 이후 | 실시간 빙고 · 알림톡 백업 · 스탬프 네트워크 · 프차 패키지 | |

**타겟 전략**: 영업 우선순위는 **토스포스 사용 가게** (서비스 코드 30초 설치로 주문→포스 자동 = 태그히어급 경험을 즉시 제공). 레거시 포스 가게는 주문 보드 태블릿을 포스 앞에 거치하는 우우 방식으로 커버 — 기능상 동작하지만 사장님 수동 이기입이 남으므로 2순위.

## 7. 파일럿 가게에서 받아야 할 것

1. **포스 기종** — 토스포스 여부가 1순위 확인 사항 (타겟 전략상 토스포스 가게 우선)
2. 가게명·혼술맵 스팟 여부 (없으면 등록부터)
3. 좌석 구조: 구역·좌석 수·바석/테이블석 — 사진 한 장이면 충분 (배치도는 사장님이 에디터로 직접 그리는 게 최종, 우리는 초기 세팅만 도와줌)
4. 메뉴판 최신본 (사장님이 직접 입력하는 게 기본, 네이버 임포트는 초기 수고 덜어주는 시드)

컨셉 확정: **소셜 모드 풀 온** (체크인·좌석맵·퀘스트·게임 전부) — 이게 해자. 조용한 바용 "주문만" 모드는 토글로 존재하되 파일럿은 풀 온으로 검증.
```
